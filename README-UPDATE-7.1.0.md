# Monthly Expense — Update 7.1.0

هذا التحديث يضيف نظام إصدار مرحلي بحيث لا يصل أي إصدار جديد للمستخدمين قبل أن يراه مالك الصفحة ويعتمده.

## ما الذي يضيفه؟

- **قناة تجريبية للمالك فقط:** عند رفع إصدار جديد داخل `public/releases/<version>/` يبقى الإصدار المستقر للمستخدمين كما هو، بينما حساب `super_admin` فقط يرى النسخة الجديدة.
- **زر اعتماد داخل التطبيق:** يظهر للمالك شريط واضح أعلى الصفحة مع زر **اعتماد وإرسال للمستخدمين**.
- **تحديث فوري داخل التطبيق:** بعد الاعتماد يرسل `ReleaseHub` رسالة WebSocket فورًا لكل الأجهزة المفتوحة، فيظهر شريط التحديث مباشرة.
- **إشعار خارج التطبيق:** بعد أن يفعّل المستخدم إشعارات التحديث مرة واحدة، يسجل الجهاز Web Push subscription. عند اعتماد الإصدار يرسل Cloudflare Worker إشعار Push لكل الأجهزة المسجلة.
- **لا توجد خدمة مدفوعة إضافية:** مفاتيح VAPID يتم إنشاؤها تلقائيًا مرة واحدة داخل Durable Object وتبقى محفوظة هناك.
- **الإبقاء على التحديث اليدوي والنسخة الاحتياطية:** المستخدم يرى إشعار التحديث لكنه يضغط بنفسه على «تحديث الآن»، ويمكنه أخذ نسخة احتياطية قبل ذلك.
- **ضريبة 5% التلقائية محفوظة:** الإصدار 7.1.0 يتضمن منطق حساب الضريبة تلقائيًا من المبلغ قبل الضريبة.

## الملفات الجديدة/المعدلة

- `src/update-entry.js` — بوابة الإصدار + API التحديث + Durable Object جديد باسم `ReleaseHub`.
- `wrangler.jsonc` — يجعل `update-entry.js` نقطة الدخول ويضيف `UPDATE_HUB` ومسار الإصدار.
- `public/releases/7.1.0/index.html` — النسخة المرشحة للمالك.
- `public/releases/7.1.0/sw.js` — Service Worker للإصدار 7.1.0 مع Push Notifications.
- `public/release-manager.js` — واجهة اعتماد المالك، إشعار المستخدم، WebSocket، Web Push، وحساب VAT 5%.
- `public/sw.js` — النسخة المستقرة الحالية 7.0.6، تبقى كما هي حتى اعتماد 7.1.0.

## طريقة الرفع

ارفع محتويات هذه الحزمة فوق ملفات المستودع الحالي **مع إبقاء `src/index.js` وباقي ملفات المشروع الحالية كما هي**. ثم نفّذ Deploy على Cloudflare بالطريقة المعتادة (`npm run deploy` أو من الربط التلقائي إن كان مفعّلًا).

بعد النشر سيقوم النظام تلقائيًا بإنشاء حالة:

- Stable: `7.0.6`
- Candidate: `7.1.0`
- Status: `owner_testing`

المستخدم العادي يستمر في 7.0.6. المالك المسجل بحساب `super_admin` يرى 7.1.0 فقط. بعد التجربة يضغط المالك **اعتماد وإرسال للمستخدمين**؛ عندها يصبح 7.1.0 الإصدار المستقر فورًا.

## إشعارات iPhone

على iPhone/iPad، إشعارات Web Push تعمل لتطبيق الويب عند إضافته إلى **الشاشة الرئيسية** وفتحه كتطبيق مستقل، ثم الضغط على **تفعيل إشعارات التحديث** والسماح بالإشعارات. لا يمكن للموقع تجاوز رفض المستخدم أو إعدادات iOS.

الخادم يرسل الإشعار فور اعتماد الإصدار، لكن توقيت ظهور Push الفعلي قد يخضع لإدارة iOS/Android للبطارية والإشعارات، لذلك لا يمكن ضمان زمن وصول بالثانية. داخل التطبيق المفتوح، WebSocket يعرض التحديث فورًا تقريبًا.

## ملاحظة مهمة لأول انتقال فقط

الأجهزة التي ما زالت على 7.0.x لم تشترك بعد في Web Push ولم يكن لديها Update WebSocket العام. لذلك **الإصدار 7.1.0 نفسه** هو تحديث تأسيسي: بعد أن يثبته المستخدمون ويفعّلوا الإشعارات، تصبح كل الإصدارات التالية Owner-first مع الإشعار الفوري داخل وخارج التطبيق. الأجهزة القديمة ستكتشف 7.1.0 عبر آلية التحديث الحالية عند فتح التطبيق أو فحص التحديث الدوري.
